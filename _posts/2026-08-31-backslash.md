[直前の投稿](https://eiu2.github.io/2026/08/30/regex.html)
で正規表現の話が出ました。正規表現には Perl 互換のものと、伝統的なものに近いものがあります。普通に使うのは GNU のツール類かと思いますので、大抵の場合は GNU の正規表現ライブラリに由来する場合のだいたい二通りになるのではないかと思います。

これも前の投稿で書きましたが、UNIX あるあるとして、ちょっと正規表現を使うとなると、それら二つをおぼえて使いわけなければならないことになることが多いです。

たとえば、私は普段はだいたい Emacs を使っています。システム・ファイルや `.emacs.d/init.el` を編集するときは、vi(今日ではほぼ Vim だと思って間違いないです)をつかいますが、まあ、だいたいは emacs です。で、emacs で正規表現を使う際には当然 GNU の正規表現をつかわないといけません。「perl や python とかを使えばいい！！」という話なのですが、現在編集中のバッファ(メモリ中におかれたファイルに結びつけられた状態のものをこういいます)で正規表現をつかって置換するのに、外部コマンドで置換して、再び読み込むとなると、ファイルの扱いが面倒になります。バッファとファイルが違ったら面倒になることこの上ないです。

で、新しい Mac になってからの話ですが、次のような Markdown のファイル

~~~
### Secion 1.2 Exercise
Vocabulary Check,
1 -- 4,
9 -- 20,
21 -- 32,
57 -- 64,
65 -- 70,
81 -- 88
~~~

を編集していて、セクションのタイトル以外は箇条書きにしたくなりました。
この場合は行頭にマイナスをつければいいので、
`M-x replace-regexp` として、
`¥(^[0-9V]¥)` を置換前のパターンとして、
`- ¥1` を置換後のパターンとしました。
これなら、上記を

~~~
### Secion 1.2 Exercise
- Vocabulary Check,
- 1 -- 4,
- 9 -- 20,
- 21 -- 32,
- 57 -- 64,
- 65 -- 70,
- 81 -- 88
~~~

とできますから。

しかし、そもそも `¥(^[0-9V]¥)` なるパターンはファイル中にはないという反応をされます。

「ああ！！わかった。**バックスラッシュ**を重ねないといけないんだっけ？」

と思って、今度は `¥¥(^[0-9V]¥¥)` で挑戦しましたが、そんなパターンはないといわれ、だめでした。

あれこれやってもだめ、しょうがないので `sed` をつかって

~~~
$ sed - e 's/\(^[0-9V]\)/- \1/' some.md
~~~

とやったら思ったようにできました。

不思議です。

用はこれですんだのですが、気持わるくてしょうがありません。

問題は多分 emacs の方にあります。いや、正確にいうと emacs の使い方というか設定にあります。

多分、この問題は若い世代の人には不思議でもなんでもなく、何がわるいのかあたり前にわかるかと思います。逆に、MS-DOS なんかに触れたり、ちょっと古い世代の日本製の PC を使っていた人には若干不思議だと思います。

こたえは、`¥` です。円記号。

これはそもそも `/` とは違うので、正規表現がだめなのは議論の余地もありません。比較的最近の世代の人はそう思うでしょう。しかし、ある世代より前の人間は、円記号とバックスラッシュは同じなのです。

そんな馬鹿なと思うかもしれませんが、昔は TeX のファイルを見ても円記号の嵐でした。それがいやで、修士論文をタイプするときは、学科の一番いい Sun (そうなんです！！まだ Sun Microsystem があった時代の話です) のワークステーションで入力してました。円記号まみれの TeX ファイルなんて見たくなかったからです。でも、そんなわけにもいかず、kermit かなんかで繋いだ PC の端末を使わないといけないこともありました。その場合は TeX ファイルが円記号まみれになって、ずいぶんと惨めな気分になりました。その後も、個人で PC が買えるようになっても、ずっと画面に表示されているのは円記号でした。なので、円記号とバックスラッシュは同じものとすりこまれてしまったのです。

しかも、Linux やら FreeBSD やらが普及しても、最初のうちは、設定がわるいとやはり円記号がバックスラッシュのかわりだったりします。いまでも、terminal なんかは設定をちゃんとしないと円記号がバックスラッシュだったりすのは普通のことでしょう。

はい。答えあわせです。

なので、emacs を使っていても、円記号が出てくるのになんの抵抗もなくなっていたのです。若いうちは神経質になったことでも加齢とともに鈍感になってくる。感性の敏感さが摩滅していくので、最初のうちのような円記号に対する嫌悪感はなくなっていました。それが原因です。古い Mac を使っていたときにはどうだったか忘れましたが、最初から全部バックスラッシュだったと思います。キーボードは JIS キーボードなので、ひょっとすると、自分でもわすれただけで「システム設定」かなんかで、円記号は全部バックスラッシュにするように設定していたのかもしれません。

ちなみに、円記号 `¥` は `\u00a5` で、バックスラッシュ `\` は `\u005c` と文字コードすら違っているというのが今の扱いのようです。なので、文字コードがそもそも違うので、正規表現の
`¥(^[0-9V]¥)` が `\(^[0-9V]\)`
と別物なのはあたり前の話です。

いまではそうなっているのかと知って愕然としました。いや、知らないのは私だけだったのかもしれませんが。

ちなみに、これを解決する方法を検索したら AI 検索の人が `.emacs.d/init.el` に
次を入れるといいよと教えてくれました。

~~~
;; 「¥」キーでバックスラッシュを入力する
(define-key global-map [?¥] [?\\\\ edge])
(define-key global-map [?\M-¥] [?\\\\ edge])

;; もし上記でうまくいかない場合は、以下も試してください
(define-key global-map [?¥] "\\")
~~~

なので、私は現在は

~~~
(define-key global-map [?¥] "\\")
~~~

でやっています。円記号なんか使う機会はないので困りません。

ちなみに、これも調べたのですが、もしも、上のように設定した場合に円記号を
入力したくなったらどうするか？ ですが、
`C-x 8 RET`
してから、文字コード `00a5`
を入れれば、問題なく入力できます。
まあ、例によって知らないのは私だけの tips でしたが。

**(蛇足)** `C-x 8 RET` を使うと前回の NBSP も入力できます。
これは昨日知ったばかりです。ちなみに、NBSP を入れたプログラムを各コンパイラがどう扱うかのテストをやったときにはそれを知りませんでした。

では、どうやったかですが、
~~~
package main

import "fmt"

func main() {
	fmt.Println("#include <stdio.h>\n\nint main() {\u00a0 printf(\"hello, world\");}\n");
}
~~~

などのような Go プログラムをつくって C, Go, Rust のプログラムを作っていました。

なぜ、Go かというと、unicode の出力がいちばん面倒がないからです。`\u00a0` とかを
`fmt.Println` に入れればいいだけです。やっぱり、Ken Thompson が作った言語のことだけはありますね。Unicode の扱いも楽でいいです。

Rust の方はまだちょっとピンときてないです。まあ、同じなのかもしれませんが。
