以前に Go というプログラミング言語を勉強することになったのですが、一通り文法とかを勉強してから、理解を深めるために、ありがちなプログラムを書いてみました。よくいわれるように、プログラムを習得するのにはどんどん書くのがいいというわけです。ちなみに、すごく恥しいのですが、どんなプログラムを書いたのかと、まあ、hello world プログラムや FizzBuzz プログラムは書くわけですが、次に echo プログラムみたいなものを書いて、それから、cat コマンドみたいなものを書きました。

あと、数学の問題プラス解答が書いてあるファイルを読んで問題と解答を別々のファイルに書き出してから LaTeX にかけて pdf を作成するようなものも書きました。まあ、これなんかは、シェルスクリプトで書くべきものなのでしょうが、練習をかねて Go で書いてみました。なんか、どうでもいいような使い捨てプログラムもいいところですが、いまでも実用的につかっています。

という感じで、上記のようなプログラムを書くのが、私個人の定番コースですが、あとはネタ切れを起してどうしようかと思っていたら、競技プログラミングというものを知りました。日本だと AtCoder ですね。

で、だいたい毎週土曜日の晩にコンテストがあるのですが、いや、昨日のは自分史上まれにみる悲惨な結果でした。もう、死んだほうがいいんじゃないか？ ってぐらいひどかったです。正直、これで人にプログラミングを教えてはいけないんじゃないか？ と思って、頭をかかえています。

で、何がひどかったのかというと、成績は 7 題ある問題のうち、A 問題と B 問題の二題しか解けませんでした。ちなみに、上記でお話した Go の練習をやっていたときには結構 C 問題まで解けていたと思うのですが、最近は A, B の二題どまりです。情けないです。ただ、解けたが二題でも内容がもう悲惨でした。

A 問題が 7 回提出してやっと合格(AC) でした。つまり、6 回も間違っていたわけです。もちろん、A 問題のレベルで、メモリ・オーバーフロー (MLE) や制限時間オーバー (TLE) を出すわけはないので、純粋に間違っていました。つまり、WA (wrong answer) です。

6 回ですよ！

ちなみに、1 回まちがうと、ペナルティが 5 分つくので、A 問題だけで 30 分のペナルティをくらったことになります。しかも、正答を提出できたのが、開始後 20 分以上たってからなので、A 問題だけに 50 分以上かかった計算になります。

ちなみに、問題ですが、
[ABC467 の A 問題](https://atcoder.jp/contests/abc467/tasks/abc467_a)
にありますが、
体重(キログラム)と身長(センチメートル) が与えられたときに、
BMI を計算して、25 以上かどうかを判定するプログラムを作成すればいいだけです。

例によって、「楽勝〜」とばかりにコードを書いて投稿しました。
滅茶苦茶はずかしいのですが、コードは以下のようです。

~~~ C++
#include<iostream>
using namespace std;
int main() {
  double H,W;cin>>H>>W;
  H /= 100.0;
  double BMI= W/(H*H);
  if(BMI>=25.0)
    cout<<"Yes"<<endl;
  else
    cout<<"No"<<endl;
  return 0;
}
~~~

ちなみに、問題を正確にいうと体重は
$1 \leq W \leq 300$
の範囲の整数で与えられます。単位はキログラムです。
身長も
$1 \leq H \leq 300$
の範囲の整数として与えられます。単位はセンチメートルです。
BMI は身長を $H$ **メートル** としたときに、
$W \div H \div H$
で与えられます。
この身長がセンチメートルで与えられているのに、
BMI の計算の際にはメートルでやらなければならないというのが曲者です。

ただ、そもそも BMI が 25 以上というのは、25.0 なわけで、
これは整数でない。浮動小数点型なので、そこは深く考えなくてもいいと思っていました。
だいたい A 問題なので、浮動小数点型の誤差をつきつめる(というか、整数の範囲で計算して回避する)問題ではないだろうと思ったのが甘かったです。

最悪、これは C++ の固有の問題だろうと思って急遽 python で提出しましたが、
もちろんだめです。

~~~ python3
(h,w) = list(map(int, input().split()))
h/=100
if w < 25*h*h :
    print("No");
else:
    print("Yes");
~~~

そもそも、浮動小数点型の誤差っていうのはいわゆる「測定誤差」のようなランダムに起るものではなくて、
IEEE 754 の仕様に基くものなので、再現性があるという話をどこかで聞いたことがあるのですが、つまり、そうであれば、IEEE 754 に基づいて実装されている浮動小数点型を持っている言語は C++ だろうと、python だろうと同じ誤差を生じるはずです。

悩んだあげくに、最後は徹底的に整数の範囲で計算することにして、なんとか正解しました。

~~~ python3
(h,w) = list(map(int, input().split()))
if w*100*100 < 25*h*h :
    print("No");
else:
    print("Yes");
~~~

なんというか、最初からこうすればよかったのですが、思い込みで無視して、その結果散々になって、馬鹿みたいで恥しいです。

ところで、公式の解説を読むと浮動小数点を使った場合に落すようなテストケースがあるということでした。

問題はそれがどういうようなテストケースかということです。

で、この問題はそもそもが、身長も体重も整数で与えられていて、
$1 \leq H, W \leq 300$
なので、総当たりで BMI を 2 通りに計算して比較すればいいだけです。
範囲がすごく狭いので、一秒もかからず計算できるでしょう。

そこで、次のようなものを作ってみました。

~~~ C++
#include<iostream>
using namespace std;

bool dcalc(double H, double W){
  H /= 100.0;
  if(W/(H*H)<25.0)
    return false;
  else
    return true;
}

bool icalc(int H, int W){
  if(W*100*100<25*H*H)
    return false;
  else
    return true;
}

int main(){
  for(int H=1;H<=300;H++)
    for(int W=1;W<=200;W++)
      if( dcalc((double)H, (double)W) != icalc(H, W) )
	cout<<H<<" "<<W<<endl;
  return 0;
}
~~~

それで、これを実行すると、

~~~
$ ./a.out 
20 1
40 4
80 16
160 64
220 121
260 169
~~~

となりました。身長 20 センチ、体重 1 キロとか、身長 260 センチ、体重 169 キロ
とか、やや荒唐無稽なものもありますが、身長 160 センチ、体重 64 キロあたりなら、
まあ、現実的にありそうです。

ちなみに、これを計算してみると、

~~~
$ python3
Python 3.8.2 (default, Apr  8 2021, 23:19:18) 
[Clang 12.0.5 (clang-1205.0.22.9)] on darwin
Type "help", "copyright", "credits" or "license" for more information.
>>> 64/(1.6*1.6)
24.999999999999996
>>> 64*100*100
640000
>>> 25*160*160
640000
~~~

とかなるので、BMI は目一杯正確に計算しようとすると
$25$
ちょうどの整数になり、
浮動小数点だと
$24.999999999999996$
となります。つまり、浮動小数点だと微妙にやせているという判定になりますが、
整数で計算すると、ぎりぎり
$25$
以上になるというわけです。

他のケースについても、だいたい同じ感じで整数で計算した場合と浮動小数点で計算した場合
で食い違うようです。

解説には具体的な反例がなかったので、ちょっと作ってみました。たしか、どこかの
Drop Box のアカウントにコンテストのテストケースが置いてあるらしいのですが、
場所をしらなったので自分で考えてみました。
