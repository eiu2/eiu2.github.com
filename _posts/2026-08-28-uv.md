### Go と Rust

前回は古い MacBook Pro の初期化の話でしたが、その前の新しい MacBook Air のセットアップの
ほうは、まあだいたい終って、あとは Go とか Rust とかインストールする話で終っていました。
なんか、

> Go と Rust の処理系はインストールするつもりです。ただ、今日は疲れたので、あとでにしようと思います。

という感じになっていたかと思いますが、インストールされた方ならおわかりになるかと思いますが、インストールなどといっても、両方あわせても 10 分かからないぐらいの程度です。どちらも、そんなに大きなものではないので、ダウンロードに時間は大してかからないし、インストーラがついているので余程こったカスタムをしない限りはほとんど負担のない作業です。

もちろん、そんなことは私もわかっています。疲れたとはいっても、それができないほど疲れたわけでもありません。なんですが、気力がわかない。気力がわかないというのは、いいわけじみていますが、それがわかっていても、「じゃあ、やろうか！！」とはならない。

年をとるというのはこういうことなのでしょうか？

ちなみに、セットアップの投稿を読んでみると、随分と「面倒」という言葉を使っていました。「面倒」、「疲れた」などと結構後ろ向きの言葉ばかりです。まあ、ブログの更新を怠っていたのも、おなじような構造からでしょう。

### uv

ところで、前回のセットアップの投稿を gemini さんに読んでもらったら、頼んだわけでもないのですが、uv というものの存在を教えてもらいました。
[Astral 社の uv](https://docs.astral.sh/uv/)
です。

これは python の package とプロジェクト管理のためのアプリです。まあ、`pip` があるじゃん！！ っていう話になるんでしょうが、これがあると、複数バージョンの python がインストールできて管理できるというメリットがあります。当然、システムの python には触らないので、Mac で python を使うときに、自前でインストールしたいけど、anaconda 入れるのは大変だしとかいうときに、便利です。あと、とにかく、早い。あっという間に最新の python をインストールしてくれたので、助かりました。

これは、教えてもらってよかったです。

しかし、検索してみると uv については 2024 年ぐらいに解説記事が出ているようなので、二年近く知らずに過していたことになります。もちろん、私の専門はこういった分野(計算機関連、データサイエンス)ではないし、エンジニアでもないのですが、それにしても、時代から取り残されていたものだと思います。あるいは、勉強が足りないといった感じでしょうか。

なんでもかんでも加齢を原因にはしたくない(つまり、根本的に性格とかが原因でもあるので)のですが、頻度的にはそういうのが増えてきているのは間違いないです。基本的に過去に習得した方法論でなんとかなるという考えがあって、それが色々妨げになっているように思います。

まあ、そんなことをいってもしょうがないですね。話を元に戻しましょう。

パッケージはプロジェクト毎にいれるみたいなので、私みたいに、`/tmp` あたりにちょこちょことスクリプト書いて実行するみたいないい加減な使い方をしていると、ちょっと敷居がたかいです。Rust の cargo でも、いちいちプロジェクトを作ってからやるので、面倒がって個人的には rustc ばかり使っています。

ああ、ここでもまた「面倒」がでてきてしまった……。

愚痴はともかく、それで思ったのですが、uv が Rust で書かれていることと関係があるのでしょうか？ uv のイメージは python の cargo 的な位置付けで考えるといいのかもしれません。

Rust もあんまり cargo が使えていないんですよね。ちょっと正規表現を使いたいだけなのに、ディレクトリを掘って、プロジェクトを初期化して……。というのが、すごく大袈裟な感じがします。

というか、そもそも、/tmp に転がして使い捨てにするようなものを Rust で書くのは間違っているような気もしますが……。こういうのは python でも大袈裟で、sed か awk あるいは perl でも使った方がタイパはいいのかもしれません。

ああ、適材適所とかいう陳腐だけど正論な結論になっただけでした……。

ちなみに、Kernighan が "The Go Programming Language" を執筆したのに
[groff を使ったという話](https://rkrishnan.org/posts/2016-03-07-how-is-gopl-typeset.html)
を聞いて愕然としました。あの C 言語の本以来、何冊もの本を troff で処理してきた方なのですが、いまさら、troff ですよ！！ いまさら！！

だから、こういう話を聞くとついつい使い慣れたツールでいいじゃん！！とかなりそうになりますけど、Kernighan のメールを見ると、ちゃんと必要なアップデートがされているのと、groff を使うのにちゃんと理由があるので、なんというか、メールの文の深さみたいなのが感じられて、格の違いというのはあるにしても、あまりに違いすぎるので、あたりまえにしても、いやになってしまいます。

話が脱線しました。

とりあえず、パッケージとかを追加する方法があまり理解できていないのですが、もう少し研究してみることにしてみます。たとえば、いつかのプロジェクトを立てるとして、それらがいずれも pandas を使うとしたら、その都度 pandas をダウンロードするのでしょうか？ それとも、いちどどこかに pandas をダウンロードしておいて、プロジェクトに結びつける感じになるのでしょうか？ その都度ダウンロードすると大袈裟だなあとは思っていたら、
`uv pip --system`
みたいな感じの操作が一番わたしのイメージに近い感じなのですが、ドキュメントを読むとあんまりお勧めでないニュアンスで書いてあって、ちょっと一通りドキュメントを読まないとわからない感じです。


ただ、uv は教えてもらってよかったです。まあ、いまさらなんですけど。
