なんか、だらだら投稿が続いていますが、またしても、
[直前の投稿](https://eiu2.github.io/2026/08/29/whats-happen.html)
で、

> ファイルを消去して、別ファイル名でアップロードしたり、怪しいコードブロックを削除したりもしましたが、だめでした。

とありますが、実は gemini さんから、Markdown の python のコードブロックの中に
[ノーブレークスペース (NBSP)](https://en.wikipedia.org/wiki/Non-breaking_space)
が入っているよといわれました。なんか、見た目は「半角空白」 `\u0020` と同じですが、
「全角空白」 `\u3000` 同様これがインデントのところに入っているとエラーになってしまいます。

「全角空白」がエラーになるのはともかくとして、C, C++, Go, Rust あたりは NBSP の扱いはどうなんでしょうか？ (まあ、調べればいいだけなので、あとで調べようと思います)

それはともかく、「半角」とか「全角」などという言葉がなんか、SJIS とかの時代を彷彿とさせてしまいますが、いまでも普通につかっています。しかし UTF-8 があたり前の学生でも抵抗なく受けいれているのは、ちょっと不思議です。ちなみに、私も今風にスカして `\u0020` なんて書いていますが、無知な私はさっきまで何十年もずっと `\x20` でやっていました。

脱線をしてしまいました。

それで、話をもとに戻すと、gemini さんから NBSP について注意されたので、怪しそうなところを直したのですが、確認の方法で困ってしまいました。ブログの投稿記事の Markdown のコードブロックの中なので、`cat -v` をやると、日本語の部分にも反応して、わけがわかりません。C でコードを書いたりしたのですが、なぜか上手くいかず、結局 Google 検索をしたら AI 検索の人が提案してきた中に

~~~
grep -P '\x{00A0}' testuv.py
~~~

というような感じのものがありました(ひょっとすると、`\x{00A0}` ではなくて、`\u{00A0}` だったかもしれません。ちなみに、このコード自体は chatGPT に再現してもらったものです。何度も同じ質問をするのも悪いと思ったので……)。

問題はここからです。

これを見た私は何か違和感をおぼえました。「なんか、正規表現がおかしい。こんなことできたっけ？ あと、`grep` の `-P` オプションってなんだっけ？」

まず、これは GNU の grep であるというのはなんとなくわかったので、調べてみると……。

> Interpret patterns as Perl-compatible regular expressions (PCREs).

などとあります。

え！！ いつから GNU grep に Perl の正規表現がつかえるにようなったんですか？ そんなの聞いてないんですけど！！

なんていったものの、単純に勉強不足なだけですね。とはいっても、こういう決まりきったコマンドのバージョンなんてそもそもチェックしないし、ましてや、新機能がついたかどうかなんて気にすることなんてないので、これは盲点でした。ちなみに、GNU sed も調べたのですが、こちらは Extended Regular Expression には対応している (`egrep` モード？) ものの、さすがに Perl の正規表現には対応してるような感じじゃなかったです。

UNIX つかっているとよく遭遇する問題なのですが、perl や python (多分 python のは perl 互換の正規表現です。多分)なんかの正規表現と grep, sed の使っている正規表現が違うので、共通ですむ部分はもちろんありますが、区別しておぼえておかないといけなかったりします。Vim はわかりませんが、nvi だと、おそらく GNU grep のに近いはずです。あと、Emacs も GNU grep 方式なので、大変です。何が大変かっていうと、グルーピングのかっこにバックスラッシュをつけないといけないのが面倒です。

たとえば、`\([hH]oge\)` みたいにです。

たまに、「えーと、どっちだっけ？ バックスラッシュ必要だったっけ？ いらなかったっけ？」となることが多くて、かならず、もたつきます。

それが、なんということでしょう！！

grep でも Perl 式の正規表現がつかえるのを昨日知ったのでした。聞いてないよ！！ って感じですが、まあ、個人的にはちょっとうれしいです。まったく、なんでいままで知らなかったんだろうと思いました。

ところで、上記で Google の AI 検索の人に何度も聞くのは悪いので、chatGPT に聞いたと書きましたが、chatGPT の方は `grep` を使った解としては

~~~
grep -n $'\u00a0' your_script.py
~~~

というのを先に教えてくれました。

これを見て、また目をまるくしてしまいました。見慣れない正規表現の指定です。しかも、今度は特に特別なオプションをつけていません。

これはいったいどうしたことでしょうか？

で、まず、剥き出しのドル記号がこれはシェルの変数だろうということがわかります。で、Bash のドキュメントをしらべたら `$'\xa0'` とかで文字コードの一文字を指定できるようなことが書いてあります。
なお、chatGPT は「MacOS の場合は」といっているのですが、残念ながら

~~~
% grep -n $'\xa0' testuv.py
grep: illegal byte sequence
~~~

こっちはエラーになるようです。
`0xff` 以下なる通るわけでもないみたいです。
もちろん `$'\u00a0'` は問題ありません。

ところで、この文字コードの指定方法なのですが、Bash のドキュメントにはありましたが、
`/bin/sh` のほうでも使えるんでしょうか？
オリジナルに近そうなマニュアルを探してみましたが、そういうのは見当りませんでした。
私がみたのは
[Manual of the Bourne Shell on Version 7](https://www.in-ulm.de/~mascheck/bourne/v7/)
というのですが、ちょっとそれについての記述を検索してもでてきませんでした。
ただ、これは AT&T UNIX の `/bin/sh` なので違うかもしれません。

それで思い出したのですが、 MacOS の grep は `strings /usr/bin/grep` すると

~~~
h@$FreeBSD$
$FreeBSD$
$FreeBSD$
$FreeBSD$
(中略)
%s (BSD grep, GNU compatible) %s
(中略)
2.6.0-FreeBSD
~~~

とか出てくるので、BSD の系譜の grep みたいです。というか、こんなまわりくどいことせず、
`grep --version` するとちゃんと正体がわかります。

~~~
$ grep --version
grep (BSD grep, GNU compatible) 2.6.0-FreeBSD
$
~~~

さらに、脱線すると `strings /bin/ls` すると

~~~
@(#) Copyright (c) 1989, 1993, 1994
The Regents of the University of California.  All rights reserved.
~~~

などとカリフォルニア大学の評議員会の著作権表示が出てきて、MacOS (というか、ベースになった darwin) は BSD ということがわかります。

なんか、みなさんご存知のことを、すごいドヤ顔で語ってしまいました。すみません。

ということで、NBSP のおかげで、なんか、GNU grep に Perl の正規表現互換モードのオプションを発見したというお話でした。

**(2026/08/30 追記)** NBSP の各言語での扱いですが、Clang の場合は

~~~
$ gcc cc.c
cc.c:3:13: warning: treating Unicode character as whitespace
      [-Wunicode-whitespace]
    3 | int main() {  printf("hello, world");}
      |             ^
1 warning generated.
$
~~~
となって、警告がでるもののコンパイルできました。

Rust と Go はエラーになりました。
